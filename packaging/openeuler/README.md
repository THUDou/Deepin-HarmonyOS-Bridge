# openEuler dsoftbus 3.2 → OpenHarmony 6.0 rebase

This directory tracks the **openEuler packaging** side of the SoftBus 6.x
migration. It is intentionally a checklist, not a fake `.spec` that claims the
port is finished.

## Inputs

| Part | Current baseline | Target |
|---|---|---|
| openEuler `dsoftbus` package | 3.2 (openEuler source package) | rebase branch `oh6-klink-p0` |
| OpenHarmony `communication_dsoftbus` | 6.0-Release `e2b2e65` | same |
| OpenHarmony `security_device_auth` | 6.0-Release `63a796a` | same |
| KLink | 4.x `5f0d585` | Linux host adapter + device-manager UX only |

## Why not just bump the spec

KLink's Linux host build is built around 4.x source paths and 143 CMakeLists.
The first OH 6.0 overlay reached CMake configure and failed because 4.x sources
such as `core/transmission/common/src/softbus_message_open_channel.c` and
`core/authentication/ipc/src/auth_client_proxy_standard.cpp` no longer exist
in 6.0. The 6.0 tree also has no CMake host build; it uses GN targets.

Therefore the packaging flow must be:

1. **P0** — generate host CMake targets from OH 6.0 `BUILD.gn` (source manifest
   is in `build/softbus6-manifest.json`, generated by
   `scripts/export-softbus6-manifest.py`).
2. **P1** — bring KLink's Linux OS adapter (ifname, socket, timer, mem, SN)
   under those targets; keep CoAP + TCP + auth only.
3. **P2** — replace KLink 4.x `device_auth` with OH 6.0 `security_device_auth`;
   PIN/PAKE first, no cloud.
4. **P3** — only then change the openEuler spec `Source0`/BuildRequires and
   produce an RPM. Do not point the 3.2 spec at 6.0 before P0/P1 pass.

## Packaging checklist

- [ ] fetch the actual openEuler 3.2 spec and list its current patches
- [ ] preserve distro patches unrelated to SoftBus
- [ ] add OH6 source manifest and generated CMake files as a patch, not a fork
- [ ] list BuildRequires (openssl-devel, sqlite-devel, cJSON, cmake, gcc)
- [ ] build in a clean openEuler chroot/container
- [ ] install test: `softbus_server` starts, one CoAP peer discovered
- [ ] Gate B: KaihongOS 6.x/OH 6.x trusted-list entry (separate gate)

## KLink integration boundary

KLink is the **Linux host adapter and 4.x-compatible lab baseline**, not a
drop-in 6.0 implementation. DHB uses KLink for:

- Linux CMake/OS adapter lessons;
- 4.x CoAP discovery lab;
- device-manager PIN UX reference.

DHB does **not** claim that KLink 4.x auth equals OH 6.x `device_auth`.
